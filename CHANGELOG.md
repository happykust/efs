# Changelog

Все значимые изменения проекта фиксируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект следует [семантическому версионированию](https://semver.org/lang/ru/).

## [1.0.1] — 2026-08-29

### Исправлено

- Каскадное `exclude: true` больше не удаляет компоненты, которые тянет кто-то
  кроме исключённых. Правило стало явным: компонент уходит, только если все его
  родители тоже помечены `exclude`. Прежде удалялось всё поддерево исключённого
  узла — пометка одного собственного модуля молча выносила из перечня сторонние
  библиотеки, которые продукт поставляет. Каскад стал на слой мельче: чтобы
  убрать длинную цепочку dev-зависимостей, помечайте и промежуточные пакеты.
  Для собственного кода правильный режим — `exclude: "direct"`: он не трогает
  зависимости вовсе.

- `efs scan` с явно заданными `--tool`, `--target`, `--output` больше не требует
  конфиг и не запускает мастер. Без конфига и без аргументов в неинтерактивной
  среде выводится подсказка, а не зависший мастер — прежде команда обрывалась
  в CI на первом вопросе.

## [1.0.0] — 2026-08-29

Первый выпуск под именем `efs-sbom`. Раздел «Изменено» описывает, чем релиз
отличается от предшественника — пакета `sbom-utils`, который не публиковался.

### Изменено (breaking)

- `efs check` возвращает осмысленный код: `0` — перечень готов, `1` — ошибки схемы
  или недоступные ссылки, `3` — схема в порядке, но перечень не заполнен. Прежде
  команда всегда завершалась с кодом `0`, из-за чего не годилась для CI. Код `2`
  оставлен за ошибками вызова, как принято в click.
- Проект переименован в **efs** (Easy FSTEC SBOMs).
  - Дистрибутив на PyPI: `efs-sbom` (имя `efs` там занято чужим пакетом).
  - Python-пакет: `sbom_utils` → `efs`.
  - CLI-команда: `sbom` → `efs`.
  - Модуль `sbom_utils.sbom_utils` → `efs.utils`.
  - Модуль `sbom_utils.cdxgen_postprocess` → `efs.postprocess` (обрабатывает вывод
    и cdxgen, и trivy, прежнее имя вводило в заблуждение).
  - Каталог кеша: `~/.cache/sbom-checker` → `~/.cache/efs`. Прежний кеш не
    переносится — при первом запуске проверки выполняются заново.
  - Имя файла конфигурации `.sbom-config.json` не изменилось.
- Удалён неиспользуемый слой argparse из модулей (`configure_parser()`, `main()`,
  `if __name__ == '__main__'`). Прямой вызов модулей вида
  `python -m sbom_utils.updater` больше не поддерживается — используйте `efs update`.
- Удалён `requirements.txt`: зависимости описаны в `pyproject.toml`, версии
  зафиксированы в `uv.lock`.

### Добавлено

- Набор тестов на pytest и конфигурация ruff.
- CI на GitHub Actions: линтер, тесты на Python 3.12/3.13/3.14, сборка пакета
  с проверкой состава wheel и запуск команд из установленного дистрибутива.
- Публикация в PyPI по тегу через trusted publishing, релиз на GitHub с дистрибутивами.
- Workflow генерации SBOM самого efs (cdxgen → postprocess → check) на релизных тегах.
- `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, шаблоны issue и pull request,
  конфигурация Dependabot.
- Пример заполненного перечня — `examples/example-sbom.json`.
- Документация в `docs/`: руководство по подготовке перечня под ФСТЭК, справочник
  команд и описание конфига. README сокращён до точки входа.
- Поле `source_langs` в конфиге: языки задаются списком или строкой и попадают в
  SBOM отдельным свойством `GOST:source_langs` на каждый язык, как требует ФСТЭК.
  Для большинства экосистем (pypi, npm, maven, cargo, golang, gem, nuget и других)
  язык определяется по типу purl автоматически; `deb` и `rpm` заполняются вручную.
  `efs config init` подставляет язык в конфиг, `efs config status` показывает
  компоненты без языка.
- Экспорт в CSV и ODT выводит все языки компонента, а не только первый.
- В графу источника отчётной формы попадает название сертифицированного СЗИ из
  `GOST:provided_by`, если ссылки на исходный код нет. Прежде графа оставалась
  пустой, хотя `efs check` считал такой компонент заполненным.
- `efs postprocess` сохраняет `description` у образов контейнеров: это графа
  «Назначение» отчётной формы, и постобработка её стирала.
- `efs check --format container` сообщает об образах без назначения.
- `efs --version` (`-V`) печатает версию.
- `efs check --check-vcs` показывает, сколько ссылок проверяется, и отмечает
  прогресс на длинных перечнях.
- Мастер `efs init` завершается проверкой готовности перечня, а результат
  постобработки пишет в отдельный файл, не перезаписывая исходный SBOM.
- `efs merge` переносит языки в сводный перечень: компонент-сервис наследует языки
  своих компонентов, включая вложенные. Прежде сводный перечень гарантированно не
  проходил проверку готовности.
- `efs update --props`, `--gost` и `--fix-all` проставляют язык, следующий из purl.
- Значения `--format`, `--tool` и `--gost-default` проверяются и подсказываются
  автодополнением; неверное значение отвергается с перечнем допустимых.
- Входные файлы проверяются на существование: вместо трассировки стека выводится
  сообщение об ошибке, а команда завершается ненулевым кодом. Прежде `efs check`
  на отсутствующем файле печатал traceback и возвращал `0`.
- `efs postprocess` проставляет `GOST:source_langs` и без конфига: язык следует из
  purl и не зависит от того, описан ли компонент в `.efs-config.json`. Прежде
  проверка требовала язык, а заполнить его без конфига было нечем.
- Компоненты, которые `efs postprocess` дописывает в конфиг, сразу получают язык,
  выведенный из экосистемы, — как и при `efs config init`.
- `efs check` проверяет готовность перечня к сдаче: заглушки `TODO` в метаданных,
  отсутствие ГОСТ-свойств и `GOST:source_langs`, компоненты без ссылки на
  репозиторий и без `GOST:provided_by`. В конце печатается сводка по видам
  замечаний. Отдельного флага нет — проверка выполняется всегда.
- `efs merge` объединяет сырые отчёты trivy: компоненты дедуплицируются по purl,
  уязвимости — по CVE, зависимости пересопоставляются, компоненты-манифесты и
  висячие ссылки отбрасываются. Смешивание trivy-отчётов с обычными SBOM
  завершается ошибкой.
- `NOTICE` с атрибуцией ИСП РАН как автора исходного проекта sbom-checker.
- Поддержка значения `exclude: "direct"` в конфиге — исключение самого компонента
  без каскадного удаления его транзитивных зависимостей.
- Резолверы VCS-ссылок для PyPI, npm, Maven, RPM и Deb в `efs update`.
- Параллельная обработка purl при поиске VCS-ссылок.
- Команда `efs config migrate` — была описана в README, но отсутствовала в CLI.

### Производительность

- Проверка уникальности элементов вынесена из JSON Schema в отдельный линейный
  проход. jsonschema сравнивает элементы массивов попарно, из-за чего `efs check`
  на перечне с тысячами зависимостей работал квадратично: полная проверка
  реального SBOM (6933 компонента, 6892 зависимости) занимала 39 секунд, а
  на 100 000 компонентов не завершалась за разумное время. Стало 11 и 47 секунд
  соответственно, для валидного перечня на 1370 компонентов — около секунды.

### Исправлено

- Сопоставление purl в `exclude` учитывает версию: запись `pkg:npm/ajv@6.12.6`
  больше не удаляет из SBOM все версии `ajv`.
- Каскадное `exclude: true` действительно удаляет транзитивные зависимости, как и
  описано в документации. Прежде корни графа вычислялись уже после отбрасывания
  рёбер исключённого компонента, из-за чего его зависимости сами становились
  корнями и сохранялись — каскад не работал ни в одном практическом случае.
  Защита от удаления «осиротевших» рантайм-зависимостей сохранена: корнями
  считаются узлы без входящих рёбер в исходном графе.
- HTTP-фоллбэк при таймауте `git ls-remote` — крупные репозитории (например,
  chromium) больше не помечаются как недоступные.
- Неинтерактивный режим для `svn ls` и `hg identify` — проверка VCS не зависает
  в ожидании ввода учётных данных.
- Тайм-ауты для всех HTTP-запросов в `efs update`.
- `efs check --check-source-distribution` завершался исключением на каждой ссылке:
  `is_archive_url` вызывался без HTTP-сессии. Ошибки внутри параллельных проверок
  больше не игнорируются — файл не объявляется корректным.
- `rich` добавлен в явные зависимости: модули использовали его, полагаясь на
  транзитивную установку через typer.

## Предыстория

Проект вырос из `sbom-checker` (ИСП РАН) и до переименования назывался
`sbom-utils`: единая CLI-точка входа, единый конфиг, команды `check`, `update`,
`merge`, `postprocess`, `scan`, `export`, `config`, `init`. Под именем `sbom-utils`
пакет не публиковался, поэтому первым выпуском считается 1.0.0 под именем
`efs-sbom`.
